## ABstract系统简介
ABstract是一个AB 测试脚手架系统，提供一个简单易用的AB测试系统，帮助用户快速搭建AB测试环境，进行AB测试实验。
系统提供了实施AB测试需要的基本的实验、特性、配置管理及下发能力，以及基本的实验分组统计功能。

## 主要功能
### 特性（Feature）管理
特性即实验要验证的功能点，系统提供了特性的创建、编辑、删除、查询等功能。
同时提供了配置模版功能，用于配置特性的配置项，以及配置项的默认值。

### 特性配置（FeatureConfig）管理

特性配置用于控制特性承载应用中对应特性的表现，比如新旧功能开关，或者具体展示文案/样式等。

特性配置可根据特性中的配置模版自动生成，支持灵活的配置数据结构，可以减少很多配置开发工作。

另外特性配置可以设置生效时间，以及生效范围，比如特定用户、特定地区等。

特性配置状态包括：草稿、已发布、撤销、已过期等。

草稿、已过期状态的配置不会生效，已发布且在有效期的配置可以通过C端接口查询生效。

> ***特性管理配合特性配置管理可以作为日常客户端配置管理配置使用，也可以作为AB测试的实验后特性固化的配置。***

### 实验（Experiment）管理

实验是AB测试的基本单元，实验包含了实验的基本信息、实验的分组及分组配置、实验关联特性。

分组对应的配置也会根据特性配置模版自动生成。

实验状态包括：草稿、数据收集阶段、实验结果分析阶段、实验结束阶段。

草稿状态下，C端不会获取到实验对应的配置。

 - 数据收集阶段

   如果用户没有分组记录，会随机分配一个分组，并固化为对应的配置。对于不满足分组条件的用户，会固化为默认配置。当实验生效范围改变时，默认配置的用户会重新进行分组计算。
   已有分组记录的用户会根据已有分组结果返回对应分组的配置。

 - 实验结果分析阶段

   数据收集时间过后，进入实验分析阶段，该阶段会停止对新访问的用户进行分组，返回默认配置，已有分组用户会根据已有分组结果返回对应的配置。

 - 实验结束阶段
   
   过了实验截止时间后，实验进入结束阶段，实验结束后，将自动切换请求到实验配置，实现实验结果固化。

   因此管理员应在实验截止时间前在实验配置管理模块配置固化的配置。

   管理员也可手动提前截止实验，进入实验结束阶段。

## 实验配置步骤
1. 创建特性
2. 创建特性配置
3. 创建实验
